# 自律改善ループ (Autonomous Improvement Loop)

## 概要

このスキルは、QA → Fix → Refactor の3フェーズを1ラウンドとして、指定した時間またはラウンド数に達するまで自動でコード品質を改善し続ける自律改善ループを実装します。

夜にスタートさせると朝には品質が向上した状態になっており、さらに「改善手法そのものを改善する」メタ学習ループも内包しています。

### ループ構造

```
┌─────────────────────────────────────┐
│         自律改善ループ               │
│                                     │
│  ┌──────┐  ┌──────┐  ┌──────────┐  │
│  │  QA  │→│ Fix  │→│ Refactor │  │
│  └──────┘  └──────┘  └──────────┘  │
│      ↑                    │         │
│      └────────────────────┘         │
│        (指定ラウンド/時間まで繰り返し)│
└─────────────────────────────────────┘
```

### 安全機構

- E2Eテストによる自動検証
- テスト失敗時の自動 Revert（暴走防止）
- ラウンドごとの振り返り記録（メタ学習）

---

## 手順

1. **事前準備**
   - 対象リポジトリのルートに移動する
   - E2Eテスト / ユニットテストが実行可能な状態を確認する
   - `IMPROVEMENT_LOG.md` がなければ自動作成される（ラウンド記録用）

2. **パラメータを指定してスキルを起動する**
   - `MAX_ROUNDS`：最大ラウンド数（例: 10）
   - `MAX_MINUTES`：最大実行時間（分）（例: 480 = 8時間）
   - どちらか先に到達したら終了

3. **QAフェーズ（自動バグ発見・Issue起票）**
   - コードを静的解析・テスト実行・レビューしてバグや改善点を発見
   - 発見した問題を GitHub Issue または `ISSUES.md` に起票

4. **Fixフェーズ（Issue修正・クローズ）**
   - 起票された Issue を優先度順に修正
   - 修正後にテストを実行し、失敗した場合は自動 Revert

5. **Refactorフェーズ（コード品質向上）**
   - 重複排除・命名改善・設計パターン適用などのリファクタリングを実施
   - 修正後にテストを実行し、失敗した場合は自動 Revert

6. **ラウンド振り返り（メタ学習）**
   - 各ラウンドの成果・失敗・改善手法を `IMPROVEMENT_LOG.md` に記録
   - 次ラウンドの戦略を更新（メタ学習ループ）

7. **終了条件チェック**
   - ラウンド数または経過時間が上限に達したらループを終了
   - サマリーレポートを出力

---

## プロンプト

以下のプロンプトをそのまま Claude Code に貼り付けて使用してください。
パラメータ部分を環境に合わせて変更してください。

```
# 自律改善ループ実行指示

あなたはコード品質を自律的に改善するエージェントです。
以下のパラメータと手順に従って、QA → Fix → Refactor の3フェーズループを繰り返してください。

## パラメータ
- MAX_ROUNDS: 8          # 最大ラウンド数
- MAX_MINUTES: 480       # 最大実行時間（分）
- TARGET_DIR: ./src      # 改善対象ディレクトリ
- TEST_COMMAND: npm test # テスト実行コマンド
- E2E_COMMAND: npm run e2e # E2Eテスト実行コマンド（任意）

## ループ開始前の準備
1. 現在時刻を記録し、終了予定時刻を計算する
2. `IMPROVEMENT_LOG.md` が存在しない場合は作成し、ループ開始を記録する
3. テストコマンドを実行し、ベースラインのテスト通過状態を記録する
   - テストが最初から失敗している場合は、その旨を記録した上で続行する

## ラウンドループ（MAX_ROUNDS または MAX_MINUTES に達するまで繰り返す）

### フェーズ1: QA（品質調査・Issue起票）
以下の観点でコードを調査し、`ISSUES.md` に問題を起票する:
- バグ・潜在的なバグ（null参照、境界値、競合状態など）
- テストカバレッジの欠如
- パフォーマンス問題（N+1クエリ、不要な再レンダリングなど）
- セキュリティリスク（インジェクション、認証漏れなど）
- コードの可読性・保守性の問題
起票フォーマット: `[ISSUE-{番号}] {重要度: HIGH/MED/LOW} {タイトル}: {詳細}`

### フェーズ2: Fix（Issue修正）
1. `ISSUES.md` から未クローズのIssueをHIGH優先で選択する
2. 修正を実装する
3. `{TEST_COMMAND}` を実行する
   - テスト通過 → `ISSUES.md` のIssueを `[FIXED]` としてクローズ
   - テスト失敗 → git で変更を Revert し、Issueに `[REVERT]` を記録して次のIssueへ
4. E2E_COMMAND が設定されている場合は追加で実行する

### フェーズ3: Refactor（品質改善）
以下のリファクタリングを1〜3個選んで実施する:
- 重複コードの関数・モジュール化
- 変数・関数名の明確化
- 複雑な条件式の分解・早期リターン化
- 不要なコメント・デッドコードの削除
- 適切なデザインパターンの適用
修正後に `{TEST_COMMAND}` を実行し、失敗した場合は Revert する。

### ラウンド終了: 振り返り記録（メタ学習）
`IMPROVEMENT_LOG.md` に以下を追記する:
```
## Round {N} - {日時}
- 発見したIssue数: X件
- 修正成功: X件 / Revert: X件
- リファクタリング実施: X件
- 今ラウンドで効果的だった手法: ...
- 次ラウンドで重点的に見るべき領域: ...
- 現在のテスト通過数: X / 全テスト数: X
```
次ラウンドでは、この振り返りを参考に調査の優先領域を調整すること。

## 終了条件
以下のいずれかを満たしたらループを終了する:
- 経過時間が MAX_MINUTES を超えた
- ラウンド数が MAX_ROUNDS に達した
- 未クローズのIssueがゼロになり、リファクタリング候補も見当たらない

## 終了時サマリー
ループ終了後、以下のサマリーを出力する:
- 総ラウンド数・総実行時間
- 修正したIssue総数
- Revertした件数
- リファクタリング実施総数
- テスト通過率の変化（ベースライン → 最終）
- 最も効果的だった改善手法 Top3
- 次回ループへの推奨事項

それではループを開始してください。
```

## カスタマイズ例

### 短時間の試運転（30分・3ラウンド）

```
- MAX_ROUNDS: 3
- MAX_MINUTES: 30
- TARGET_DIR: ./src
- TEST_COMMAND: npm test
```

### 一晩フル稼働（8時間・無制限ラウンド）

```
- MAX_ROUNDS: 999
- MAX_MINUTES: 480
- TARGET_DIR: ./src
- TEST_COMMAND: pytest
- E2E_COMMAND: pytest tests/e2e
```

### フロントエンドプロジェクト向け

```
- MAX_ROUNDS: 10
- MAX_MINUTES: 240
- TARGET_DIR: ./src/components
- TEST_COMMAND: yarn test --watchAll=false
- E2E_COMMAND: yarn cypress run
```

## 追加の指示・注意事項

- **必ずテストが存在するリポジトリで使用してください。** テストなしでは自動 Revert の安全弁が機能しません。
- **git リポジトリであることが前提です。** Revert に `git checkout` または `git restore` を使用します。
- 初回は `MAX_ROUNDS: 3` / `MAX_MINUTES: 30` の短時間で動作確認することを推奨します。
- `ISSUES.md` と `IMPROVEMENT_LOG.md` は `.gitignore` に追加するか、ループ後にコミットするか、運用に合わせて決定してください。
- Claude Code の `--max-turns` オプションを十分大きな値（例: `--max-turns 200`）に設定して実行することを推奨します。
- コスト管理のため、`MAX_MINUTES` による時間上限を必ず設定してください。
